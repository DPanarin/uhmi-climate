# Що покращити в API (api.uhmi.org.ua)

Спостереження зроблено під час роботи з API для прототипу. Кожен пункт — невелика зміна на сервері.

| # | Зараз | Пропозиція | Що дасть |
| --- | --- | --- | --- |
| 1 | Відповіді без стиснення | Увімкнути gzip/brotli | Ряди проєкцій стиснуться в ~6 разів (47 → 8 КБ), спостережень — у ~3 рази; графік швидше відкриватиметься на мобільному інтернеті |
| 2 | Немає заголовків кешування | `Cache-Control: public, max-age=86400` (дані змінюються рідко) | Повторні відкриття без запиту до сервера, менше навантаження |
| 3 | Невідома територія → помилка 500 з HTML | 404 з коротким JSON (`{"error": "unknown place"}`) | Помилку користувача видно відразу, сервер не виглядає «зламаним» у моніторингу |
| 4 | Сезонні ряди спостережень не відсортовані | Сортувати за датою | Клієнтам не треба сортувати самим |
| 5 | Числа передаються рядками (`"1.23"`) | Передавати числа | Менший обсяг, без перетворень на клієнті |
| 6 | Ключ API у кожному запиті з браузера | Перевіряти термін дії (`exp`), періодично змінювати ключ, обмежити домени (CORS) | Ключ, видимий у браузері, не можна буде використовувати вічно |
| 7 | Немає опису API | Опис OpenAPI (Swagger) | Іншим розробникам і дослідникам легше користуватися даними |
| 8 | Значення для карти є лише всередині коду сайту | Endpoint зі значеннями для карти (рівень × показник × сценарій × сезон × період) | Скрипт витягування даних із сайту стане непотрібним; оновлення даних — без перебудови сайту |
