# Передача проєкту: прототип нового інтерфейсу climate.uhmi.org.ua

- Прототип: https://dpanarin.github.io/uhmi-climate/
- Репозиторій: https://github.com/DPanarin/uhmi-climate
- Поточний сайт: https://climate.uhmi.org.ua/ · API: https://api.uhmi.org.ua/

## Що це

Новий інтерфейс до тих самих даних, що й на поточному сайті. Ті самі 12 шарів:

- кліматичні проєкції Euro-CORDEX (RCP4.5/RCP8.5, 1981–2100);
- історичні спостереження (1946–2020).

Шари охоплюють ті самі території: Україна, області, райони, громади, річкові басейни, сітка, метеостанції. Часові ряди для графіків надходять з того самого API. Дані карти взято з поточного сайту без змін: 605 450 значень збігаються з джерелом. API для карти не змінювався.

## Запуск

```sh
npm install
cp .env.example .env.local   # вписати VITE_API_KEY (файл не потрапляє в git)
npm run dev                  # http://localhost:5173/uhmi-climate/
```

| Команда | Що робить |
| --- | --- |
| `npm run dev` | сервер розробки |
| `npm test` | модульні тести (Vitest, 76 тестів) |
| `npm run lint` | перевірка коду (oxlint, ESLint, Prettier) |
| `npm run build` | збірка в `dist/` |
| `npm run deploy` | збірка й публікація на GitHub Pages |
| `npm run data:extract` | крок 1 конвеєра даних: витягти дані карти з поточного сайту |
| `npm run data:build` | крок 2: зібрати файли карти в `public/data/` |
| `npm run data:check` | крок 3: звірити зібрані значення з джерелом |

## Конвеєр даних карти

Поточний сайт зберігає геометрію та значення всередині JavaScript-коду. Тому браузер завантажує 10–23 МБ ще до того, як користувач щось вибере. Прототип зберігає ці дані окремими файлами й завантажує лише потрібний рівень.

1. **`data:extract`** — знаходить файли поточного сайту за картою чанків з `index.html`, без жорстко прописаних назв. Завантажує їх у `data-raw/`: ця тека не потрапляє в git.

   Скрипт розбирає код у синтаксичне дерево (acorn) і **ніколи не виконує** завантажений JavaScript. Набори даних він розпізнає за набором полів. Також він витягує налаштування шарів, шкали, легенди та текст «Додаткової інформації».

   Наприкінці перевіряє 57 запитів до API.
2. **`data:build`** — будує файли карти:
   - TopoJSON на кожен рівень. Громади спрощено на 25 %, решту рівнів не спрощено.
   - Окремі файли значень для кожного набору даних, рівня та показника.
   - Пошуковий індекс.
   - Контури басейнів.

   Назви файлів містять хеш вмісту, тож браузер кешує їх надовго. Повторна збірка дає побайтово ті самі файли.
3. **`data:check`** — порівнює 250 випадкових значень із джерелом (допуск 0,005).

Якщо дані на поточному сайті оновляться, достатньо повторити три команди й опублікувати.

Ще краще — endpoint API зі значеннями для карти (див. «Що покращити в API»): тоді крок 1 стане непотрібним.

## Як влаштовано застосунок

- **Vue 3 + TypeScript.** Стан вибору зберігається в Pinia й повністю дублюється в адресі сторінки. Тому будь-яким видом карти можна поділитися посиланням.
- **Карта — MapLibre GL (WebGL).** Колір територій змінюється через стан об'єкта, без перебудови шару. Перефарбування 1 779 громад займає ~1 мс.
- **Графіки — Chart.js.** Їх код завантажується лише тоді, коли користувач вибирає територію. Відповіді API кешуються. Однакові запити, зроблені одночасно, об'єднуються. При помилці мережі запит повторюється один раз.
- **Інтерфейс.** Мови: українська та англійська. Налаштування відкриваються в боковій панелі, а на телефоні — в нижній. Є пошук території та перемикач періодів на карті з анімацією. Можна завантажити CSV і PNG.
- **Доступність.** Керування з клавіатури, підписи для екранних читачів, урахування налаштування «зменшити рух».

## Рішення та чому

| Рішення | Чому |
| --- | --- |
| MapLibre GL замість Leaflet | WebGL малює 1 779 громад і тисячі точок сітки без гальмування; перефарбування без перебудови шарів; векторні підписи. |
| Дані карти окремо від коду | Поточний сайт вбудовує дані в JavaScript: 10–23 МБ на першому візиті. У прототипі перший екран — ~25 КБ даних, решта рівнів підвантажується за потреби й кешується. |
| TopoJSON + окремі файли значень | Спільні межі зберігаються один раз. Зміна сезону чи періоду не перезавантажує геометрію. |
| Увесь вибір в адресі сторінки | Посилання відкриває той самий вид із тим самим графіком. Кнопки «Назад»/«Вперед» не засмічуються, бо адреса замінюється, а не додається в історію. |
| Ліниве завантаження | Графіки, налаштування, англійський словник, експорт завантажуються лише за потреби. Перший екран — менше коду. |
| Плавна шкала кольору з коренем | Невеликі зміни (наприклад, +0,3 °C) теж помітні; легенда — неперервна смуга, як і сама заливка. |
| GitHub Pages | Безкоштовний статичний хостинг для прототипу. Для постійної роботи підійде будь-який статичний сервер або CDN інституту. |

## Обмеження прототипу

- Київ (місто) не має полігону на рівні громад у вихідних даних — так само, як на поточному сайті.
- Дві станції з назвою «Ямпіль»: API розрізняє станції за назвою, тому другу окремо не запитати.
- JavaScript першого візиту: 359 КБ основний код + 142 КБ фоновий потік MapLibre.
- Safari не перевірявся. Перевірено Chrome, Firefox, телефони від 360 px.
- Аналітика (Google Analytics) підготовлена, але вимкнена. Вмикається змінною `VITE_GA_ID`.
